# Продолжение перевода от проверенного MASTER_EN

Если исправлен общий языковой валидатор или утверждён новый глоссарий, перевод
можно продолжить от завершённого второго этапа. Команды сохраняют исходный
запуск и создают отдельную цепочку результатов; повторный MinerU не запускается.

```powershell
python -m kb_creator.scripts.continue_language prepare --predecessor-run <run> --glossary <terms.json> --output <language-successor>
python -m kb_creator.scripts.continue_language submit --continuation <language-successor> --submission <draft.submission.json> --output <draft-successor>
python -m kb_creator.scripts.continue_language submit --continuation <draft-successor> --submission <proofread.submission.json> --output <final-successor>
python -m kb_creator.scripts.continue_language verify --continuation <final-successor>
```

## Выбор чтения исходника внутри перевода

Если предварительный MASTER_EN содержит `translation_source_choice_pending`,
обычная языковая подготовка требует сначала выбрать точные варианты из OCR.
Для подготовки задания и проверки записанных решений доступны команды:

```powershell
python -m kb_creator.scripts.continue_source_choices prepare <review-master> <mechanical-candidate> <new-queue>
python -m kb_creator.scripts.continue_source_choices record <new-queue> <submission.json> <new-ledger>
python -m kb_creator.scripts.continue_source_choices verify-ledger <new-ledger>
```

Ответ заполняется по `SOURCE_CHOICE_SUBMISSION_TEMPLATE.v1.json` и сохраняет
привязку к заданию. Пустое OCR-извлечение сохраняется как свидетельство, но его
нельзя выбрать вместо текста. Одинаковые чтения из разных извлечений сохраняют
все ссылки на источник. Проверка журнала заново сверяет исходные данные,
ответ и выбранные замены; она ничего не перезаписывает.

Сборка следующего MASTER_EN по этому журналу ещё разрабатывается. Успешный
`verify-ledger` подтверждает готовность решений к потреблению, а не наличие
нового мастера или готового перевода. Смысловые вопросы могут продолжать путь
к адресным комментариям итогового DOCX.

## Общий словарь CoC

Для книг «Зова Ктулху» используйте общий реестр и выбранные решения книги:

```powershell
python -m kb_creator.scripts.continue_language prepare --predecessor-run <run> --glossary <book-terms.json> --system coc --book-id <book-id> --output <language-successor>
```

Команда сама берёт `CoC/Project_Reference/Terminology/CoC_Terminology_Decisions.csv`.
При необходимости другой проверенный путь задаётся через `--shared-registry`.
В `terminology/` создаются результат объединения, контекст и отчёт конфликтов.
Общее принятое значение нельзя молча заменить книжным. При конфликте подготовка
останавливается с указанием отчёта; исходники сохраняются.

`glossary.json` содержит точные снимки обоих входов, термины, определения,
источники, область и статус решений. Эти данные передаются в `LANGUAGE_INPUT.json`
и сохраняются с языковыми артефактами. Глобальные записи `review_required`
служат контекстом; выбранный книжный вариант не становится общим правилом.
Контекстные правила из реестра различают числовую метку `SAN 44 → РАС 44`
и обычную прозу `SAN → Рассудок`. Значения и редакция механики не меняются.

Для отдельной сборки словаря есть `python -m kb_creator.scripts.compose_coc_glossary
compose --overlay <book-terms.json> --book-id <book-id> --output <new-directory>`.
Полученный `glossary.json` можно передать существующему языковому этапу.
Исторические результаты с прежними словарями сохраняются; новый словарь
требует нового задания, а не переписывания старых хешей или отметок вычитки.

Каждый `--output` должен быть новым каталогом вне предшественника. `prepare`
проверяет исходный PDF, состояние запуска, состав и реализацию второго этапа,
MASTER_EN и его привязки к источнику. Глоссарий копируется в новый результат.
Изменение кода или входных артефактов обнаруживается при следующей проверке.

Переводчик заполняет возвращённый `template_path`, сохраняя файл ответа вне
каталога неизменяемого результата. Для уже переведённых постраничных данных
есть общий `kb_creator.scripts.bind_bilingual_page_drafts`: он проверяет точное
соответствие новым заданиям и останавливается на недоказанных сопоставлениях.

При постраничном переводе читайте продолжения предложений вместе с соседними
страницами. Между частями предложения могут находиться иллюстрации и врезки:
последняя строка страницы не всегда является концом основного текста. Перевод
соседней страницы служит контекстом; повторно вставлять её содержание нельзя.
Совпадение хешей, числа строк и пустых строк проверяет привязку и структуру,
но не доказывает правильность перевода или грамматику на стыке. Такие места
должны входить в содержательное задание вычитки; обычный разрыв страницы сам
по себе не является вопросом для пользовательского комментария в DOCX.

Если уже существует проверенный результат языкового этапа с тем же английским
источником, его окончательный русский текст можно использовать как новый черновик:

```powershell
python -m kb_creator.scripts.reuse_language_draft --prior-result <old-final/result> --continuation <new-language-input> --output <new-reuse-directory>
python -m kb_creator.scripts.continue_language submit --continuation <new-language-input> --submission <new-reuse-directory/draft.submission.json> --output <new-draft>
```

Перенос проверяет старый языковой артефакт, точное совпадение MASTER_EN,
исходных семантических диапазонов и всех упорядоченных единиц. Новый словарь
проверяется до записи ответа; неизвестные или изменившиеся соответствия
останавливают перенос. Отчёт и копии прежних свидетельств сохраняют происхождение
текста. Исторический запуск не объявляется совместимым с новым кодом.
Отметки чтения не переносятся: все строки нового задания вычитки остаются pending.

После первого `submit` требуется явная вычитка всех единиц в новом задании.

Если вычитка разделена на диапазоны, объедините ответы общей командой:

```powershell
python -m kb_creator.scripts.assemble_proofread_ranges --task <proofread.task.json> --template <proofread.template.json> --part <range-1.json> --part <range-2.json> --output <assembled-review>
```

Она требует полного охвата без пересечений, точного соответствия заданию и
явных решений по каждой единице. Команда собирает уже выполненную вычитку;
создание строк ответа само по себе не доказывает чтение текста.

Второй `submit` проверяет её ответы и собирает `result/MASTER_RU.md`, ассеты,
семантические привязки и журнал правок. Автоматически проставлять отметки
вычитки команда не умеет. При ошибке сохраняется `FAILED.json`; повторная
попытка использует новый выходной каталог.

`language_complete` означает только завершение языковых этапов. DOCX, чтение
его полного текста, визуальная проверка всех страниц, переносимый пакет и
независимый выпускной обзор остаются следующими обязательными этапами.
Эта команда пока не заменяет весь пятиэтапный запуск и не сообщает о принятии
книги пользователем. Рабочая цепочка зависит от проверяемого исходного запуска;
переносимость обеспечивает отдельная финальная упаковка всех артефактов.

Следующий общий шаг: [сборка и проверка DOCX](docx-continuation.md).

## Проверенные исправления предварительного перевода

Уже рассмотренные текстовые исправления можно сохранить до окончательной
привязки перевода к MASTER_EN, не дожидаясь повторной проверки источника:

```powershell
python -m kb_creator.scripts.amend_bilingual_pages --pages <preliminary/pages> --manifest <preliminary/MANIFEST.json> --plan <reviewed-amendments.json> --output <new-successor>
```

План содержит SHA-256 исходных файлов страниц, точные пары `before`/`after`,
причины и ссылки на решения. Каждая замена требует единственного совпадения;
пересечения, устаревшие файлы и существующий выходной каталог отвергаются.
Меняется только `ru_markdown`; английский текст и остальные поля сохраняются,
неизменённые страницы копируются побайтно. Выход включает `pages/`, исходный
план и `MANIFEST.json` с журналом исправлений и обоими инвентарями.

Этот результат остаётся предварительным: `accepted:false`,
`translation_semantics_validated:false`. Для окончательного MASTER_RU нужны
сверка с финальным английским текстом и обычный языковой этап. Команда не
проставляет отметки вычитки. Она позволяет собрать исправленный рабочий DOCX,
сохранив прежнюю версию и проверяемое происхождение каждой правки.
