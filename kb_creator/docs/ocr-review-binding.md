# Привязка ранее вычитанных OCR-исправлений

`bind_ocr_reviews` переносит существующие полные исправления блоков в проверяемый
набор данных для реконструкции. OCR и исходные отчёты не изменяются.

```powershell
python -m kb_creator.scripts.bind_ocr_reviews --run-root <verified-stage04-run> --coverage <ocr-review-coverage.json> --source-review <source-review-coverage.json> --renders <reviewed-source-render-directory> --metadata <run-original-ocr-content-list.json> --output <new-bound-review-directory>
```

Входные отчёты используют `kb_creator.preliminary_ocr_visual_review.v1/v2`:
исходный PDF, набор метаданных, просмотренные страницы, точные полные блоки
`before`, `after` и причины исправлений. Индекс coverage выбирает версии
отчётов по хешам; импорт не ищет «самую новую» версию по имени или времени.

Команда проверяет:

- текущий Stage04 и все страницы исходника;
- хеши выбранных отчётов, оригинальных OCR-метаданных и просмотренных изображений;
- точный селектор `source_page / original_pipeline_ocr / raw_index`;
- полное совпадение `before` с блоком метаданных и пакета Stage04;
- отсутствие повторных селекторов, управляющих символов в `after` и конфликтов
  имён сохраняемых свидетельств.

Порядок основного текста, рамки и пустые продолжения могут быть перечислены
в разных полях отчёта. Импорт сохраняет эти явные решения отдельно. Блоки,
не упомянутые в отчёте, попадают в `unreviewed_raw_indices`; они не получают
автоматического подтверждения. Исправление для такого блока отклоняется.

Результат — `bound-corrections.json` со снимками выбранных отчётов и coverage.
Каждая правка сохраняет точный исходный текст, исправление, их хеши, пакет,
отчёт, визуальное свидетельство и причину. Это данные для механического
кандидата, не принятие реконструкции, не MASTER_EN и не выпуск книги.

Следующий этап должен явно применить эти исправления до выбора текста,
сохранить все альтернативы трёх видов и отдельно удерживать проблемы ассетов,
семантики и порядка. Сам импортёр эти ограничения не снимает.
