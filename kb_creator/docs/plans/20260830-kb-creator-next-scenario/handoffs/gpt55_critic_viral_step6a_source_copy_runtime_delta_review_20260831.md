## Findings

### P1 — The exact one-file source-copy exception misses MinerU's result-origin copy path

Evidence:

- The source-copy delta permits exactly one source duplicate, only at
  `engine/mineru_hybrid_high/_bridge_runtime/tmp/mineru-api-client-*/output/*/uploads/Call_of_Cthulhu_Viral.pdf`,
  with purpose `runtime_source_transport_copy`.
- The same delta states a negative full successor inventory assertion must show
  no second file with the admitted source hash/byte count, no copied source
  outside the one path class, and no source bytes in any output/provenance field
  except that redacted transport row.
- Installed `client.py:683-700` sets `return_original_file=True` for the public
  `mineru` CLI path under review.
- Installed `fast_api.py:849-850` converts that request into
  `f_dump_orig_pdf=True`.
- Installed `common.py:300-305` writes `<pdf_file_name>_origin.pdf` from the
  input `pdf_bytes` when original-file dumping is enabled; the hybrid path
  receives that flag through `common.py:751-754`.
- Installed `fast_api.py:590-604` packages `<pdf_name>_origin.*` into the result
  ZIP, and installed `client.py:855-863` extracts the result ZIP into the
  requested output directory.

Why this matters:

The amendment correctly explains the observed upload copy, but the proposed
exception is not complete for the same installed public CLI path. A successful
successor run can create a second admitted-source byte copy as
`*_origin.pdf` in the normal MinerU result/output flow, outside the single
allowed upload path and outside the declared one-row `runtime_source_transport_copy`
model. Under the amendment as written, the retry is likely to stop again after
expensive runtime work, or worse, an implementer could be tempted to classify an
unreviewed output-origin copy under an exception that does not name it. That
would weaken source immutability, provenance, and closed output authority.

Required remediation:

Amend the source-copy delta before execution. The amendment must choose one
explicit, testable route:

1. prove from installed public CLI/API evidence that `return_original_file` can
   be disabled without leaving the accepted pinned public `mineru` entry point,
   hybrid/high/formula/table behavior, one-launch rule, and no-wrapper/no-main-
   script boundary; or
2. explicitly model every installed source-byte copy the accepted public path
   can create, including both the upload transport file and any extracted
   `<pdf_name>_origin.pdf` result file, with exact path classes, counts, byte
   and SHA-256 equality, producer/process lineage, lifetime, cleanup authority,
   no-promotion rules, successor inventory rules, and negative assertions for
   all other source-byte copies; or
3. reject the public CLI path for this slice and return to architecture for a
   different reviewed integration boundary.

If route 2 is selected, do not call the result-origin file an asset, source
authority, publication artifact, accepted input, or ordinary reconstruction
evidence. It must be a named runtime/result transport byproduct with its own
closed purpose and deletion/retention semantics. Tests must reject a missing,
duplicate, mismatched, promoted, un-inventoried, or unauthorized-cleanup origin
copy exactly as they reject upload-copy violations.

### P2 — Cleanup timing wording should distinguish API-child cleanup from outer pinned CLI exit

Evidence:

- The source-copy delta requires automatic runtime cleanup only after result
  transfer or terminal stop and complete process-tree exit.
- Installed `client.py:1024-1028` calls `local_server.stop()` in the outer
  `mineru` CLI process finalization path.
- Installed `api_client.py:549-581` stops the local API child and then calls
  `self.temp_dir.cleanup()` before the outer `mineru` process itself has
  necessarily exited.

Why this matters:

The deletion authority is correctly separated from critic acceptance and from
predecessor-root cleanup. However, literal "complete process-tree exit" is
stricter than the installed lifecycle: the outer pinned CLI performs temporary
directory cleanup during its own finalization after stopping the local API
child. The packet should not leave the executor to decide whether the normal
installed cleanup path violates the wording.

Required remediation:

In the same amendment that resolves P1, specify the allowed cleanup actor and
timing precisely: the only automatic deletion authority is the installed
`LocalAPIServer.stop()` / `TemporaryDirectory.cleanup()` path inside the one
pinned `mineru` CLI launch, after result transfer or terminal stop and after
the local API child/descendant server tree has been stopped. Manual executor
deletion remains forbidden unless separately authorized after exact path/type/
hash verification. The two immutable predecessor roots remain out of cleanup
scope.
