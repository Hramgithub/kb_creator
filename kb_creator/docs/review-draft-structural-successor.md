# Structural review-draft successor

`prepare_review_draft_structural_successor()` copies a sealed completed review-draft author input into a fresh output and applies only reviewed structural data to copied author specs. It validates the predecessor input and evidence identities, the closed edit document, page domain, and bound marker-disposition sidecar before creating output.

The edit document uses `kb_creator.review_draft_structural_successor.v1` and contains predecessor input/evidence identities, one sealed `source_marker_dispositions` sidecar identity, page-scoped `structural_post_patches`, `retained_owner_assertions`, and `page_units`. It contains no book-specific runtime schema. Before staging, preparation reopens the predecessor's sealed decision set and page identities, then compares every patch and retained-owner source hash with the exact selected block text in the predecessor replay packet. Every reviewed list item must occur in a patch, and each patch must name a reviewed list item. Ordered composite patches may also name supporting source blocks. Explicit non-list rows cannot receive marker patches.

During authoring, existing `post_patches` still run before v2 reader replacements. `structural_post_patches` run once after those replacements and use the same exact `before`/`after`/`count` patch semantics. They cannot infer list structure or change translation wording.

For a lexical source-choice container, the author opens the successor's sealed input and supplies its structural projection context to the Stage05 proof. The proof retains the original ledger-derived R1 container and witnesses, then records a separate `structural_projection` with the current page hash, container interval, and witness intervals. The standalone reader consumer reopens that same sealed input and rederives the complete row; the row seal alone is insufficient. Pages without structural edits retain the legacy proof shape.

Simple `before` → `- ` + `before` insertions and exact leading `H`/`U`/`T` ornament replacement have a deterministic position map. A reordered page requires an `interval_map` on its reviewed patch. The map has ordered `segments` and `removed_intervals`: a copied segment names its exact half-open preimage `start`/`end`, SHA-256, and qualified source occurrences; a literal segment may add only a Markdown list marker (`-` or `- `). A removed interval names its exact `{view, raw_index}` source occurrence and may remove only its classified leading `H`/`U`/`T` ornament, immediately followed by a space and the first copied interval for that occurrence. The full classified raw source text must occur exactly once in the complete current lexical page, and the deleted page character must be at that full occurrence's start. A shorter patch preimage inside the occurrence cannot supply that position. If lexical correction changes the full raw source text, this authority cannot locate the source start and rejects the ornament deletion until a separately sealed exact source span is available. Every preimage character must be copied exactly once or be that explicitly reviewed one-character deletion. The concatenated segments must equal the declared `after` text byte for byte. A retained list owner may participate as a copied segment and cannot receive a preceding inserted marker; its identity includes the page as well as view and raw index. Equal strings remain distinct through their intervals and `(view, raw_index)` keys. Missing maps, ambiguous preimages, copied or dropped characters, and fragmented lexical witnesses are rejected.

Each retained-owner assertion also binds the predecessor's authored `markdown_span` and the active bound author definition. Only `start_line` and `end_line` may differ in its proposed definition. Preparation and independent reopening replay all page patches, then require the old span's characters, in order and exactly once, to occupy the successor definition's full line interval with identical UTF-8 bytes. A stale selector, including one that points to equal text from another occurrence, fails. Text selectors remain usable when unchanged and uniquely resolved on both pages; selector-form conversion is unsupported. Authored spans use effective Markdown, so a retained page whose effective Markdown differs from stored Markdown is rejected until an exact coordinate map exists. Every existing unordered-list owner in an edited page's predecessor spec requires an assertion; absent or duplicate assertions fail.

This helper does not make a source run terminal, accept structural decisions, validate final source semantics, or materialize a book. The caller supplies completed predecessor artifacts; normal author, verification, materialization, and later gates remain required.
