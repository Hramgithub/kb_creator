# Перенос проверенных ответов между очередями источника

После исправлений реконструкции новая очередь `SOURCE_CHOICE_QUEUE.v2.json`
может содержать вопросы, на которые уже дан явный ответ. Скрипт переносит такие
ответы, если совпадают исходный фрагмент, читаемый текст, альтернативы и
доказательства их происхождения. Изменённые вопросы остаются для проверки.

```powershell
python -m kb_creator.scripts.rebind_source_choice_submissions `
  <old-queue.json> <new-queue.json> <new-output-directory> `
  --old-submission <reviewed-part-1.json> `
  --old-submission <reviewed-part-2.json>
```

Обе очереди проходят полную штатную проверку. Старые ответы должны ссылаться на
точную старую очередь; повторяющиеся, чужие и некорректные ответы отклоняются.
Разрешены изменения проверенных координат страницы и транспортных файлов.
Текст, исходное вхождение, режим проекции и семантические доказательства должны
сохраниться. Неизвестные поля replay сравниваются консервативно.

Для выбранной строки Stage05 перенос заново открывает только authority из
`queue.final_evidence`: запись `authored.stage05_audit` должна быть точной
относительной записью рядом с sealed final evidence и совпадать с записью
replay. Файл audit проверяется до чтения и повторно перед записью результата,
затем кэшируется по идентичности файла для всех его страниц. Меняться могут
только корректные координаты `markdown_span`; locator, хеш строки, kind, raw
identity и любое другое семантическое поле остаются точными.

Выходной каталог должен отсутствовать и находиться вне каталогов исходных
авторитетных пакетов. Результат:

- `SOURCE_CHOICE_REBINDING_SUBMISSION.v2.json` — только перенесённые ответы;
- `SOURCE_CHOICE_REBINDING_TEMPLATE.v2.json` — только оставшиеся вопросы;
- `SOURCE_CHOICE_REBINDING_AUDIT.v1.json` — сопоставление и причины переноса
  или повторной проверки.

Шаблон с пустыми ответами нельзя отправлять как готовое решение. После проверки
оставшихся вопросов объедините ответы существующим `source_choice_batches`
и запишите ledger штатным recorder. Он заново проверит актуальность очереди.
Перенос не принимает реконструкцию, перевод или книгу и не запускает OCR.

Обе полные проверки могут занимать длительное время на большой книге. Сохраняйте
идентификатор работающего процесса и результат; не запускайте копию из-за
отсутствия промежуточного вывода.
